Todo lo esencial sobre servidores en Microsoft Azure

Aprende qué es un servidor en la nube, cómo crear el tuyo y qué hacer cuando algo falla. Usa el menú superior para navegar entre las secciones.

¿Qué es “un servidor de Azure”? Es un equipo de cómputo que corre en los centros de datos de Microsoft y que tú usas por internet. En la mayoría de los casos se trata de una máquina virtual (VM), aunque Azure ofrece otras formas de ejecutar aplicaciones sin administrar el servidor directamente.

Información básica

Estos son los conceptos que necesitas entender antes de crear o administrar un servidor en Azure.

💻

Máquina virtual (VM)

Un servidor virtual con sistema operativo Windows o Linux. Tú controlas el sistema, el software instalado y la configuración.

🌎

Región

Ubicación geográfica del centro de datos donde vive tu recurso. Elige una cercana a tus usuarios para menor latencia.

📦

Grupo de recursos

Contenedor lógico que agrupa los recursos de un proyecto (VM, disco, red). Al borrarlo, se elimina todo lo que contiene.

🔌

Red virtual (VNet)

Red privada dentro de Azure. Tus VM se conectan a ella mediante una tarjeta de red (NIC).

🛡️

NSG

Grupo de seguridad de red: reglas que permiten o bloquean tráfico entrante y saliente por puerto, protocolo y origen.

💾

Discos administrados

Almacenamiento de la VM. Existen opciones HDD estándar, SSD estándar, SSD premium y más, según rendimiento y costo.

Formas de pagar

Pago por uso

Pagas por el tiempo que la VM está asignada. Flexible, ideal para empezar.

Reservas / Savings Plan

Te comprometes a 1 o 3 años a cambio de un descuento sobre el precio de pago por uso.

Spot

Capacidad sobrante a bajo precio, pero Azure puede reclamarla. Solo para cargas tolerantes a interrupciones.

Importante: los precios y límites cambian con el tiempo y según la región. Consulta siempre la calculadora de precios oficial de Azure antes de decidir.

Elige una VM si…

  • Necesitas instalar software propio o heredado.
  • Requieres acceso total al sistema operativo.
  • Migras un servidor desde tu oficina.

Elige App Service si…

  • Solo quieres publicar tu aplicación web.
  • No quieres aplicar parches al sistema.
  • Buscas despliegue sencillo desde GitHub.

Elige Functions si…

  • Tu código se ejecuta ocasionalmente.
  • Quieres pagar solo por ejecución.
  • Reaccionas a eventos (archivos, colas, HTTP).

Primeros pasos: crea tu primer servidor

Opción A: desde el portal de Azure

  1. Crea una cuenta en azure.microsoft.com e inicia sesión en el portal (portal.azure.com).
  2. Busca “Máquinas virtuales” en la barra superior y pulsa Crear → Máquina virtual de Azure.
  3. Datos básicos: suscripción, grupo de recursos nuevo, nombre, región, imagen (Ubuntu, Windows Server…) y tamaño.
  4. Autenticación: en Linux usa clave SSH; en Windows define usuario y una contraseña robusta.
  5. Reglas de entrada: permite solo lo necesario (SSH 22, RDP 3389, HTTP 80, HTTPS 443). Limita el origen a tu IP cuando sea posible.
  6. Revisa y crea. En unos minutos tendrás la IP pública para conectarte.

Opción B: con Azure CLI

Instala la CLI de Azure y ejecuta estos comandos (cambia nombres y región a tu gusto):

# 1. Iniciar sesión
az login

# 2. Crear un grupo de recursos
az group create --name rg-demo --location eastus

# 3. Crear una VM Ubuntu con clave SSH
az vm create \
  --resource-group rg-demo \
  --name vm-demo \
  --image Ubuntu2204 \
  --size Standard_B2s \
  --admin-username azureuser \
  --generate-ssh-keys

# 4. Abrir el puerto 80 (web)
az vm open-port --resource-group rg-demo --name vm-demo --port 80

# 5. Conectarte por SSH (usa la IP pública que muestra el paso 3)
ssh azureuser@IP_PUBLICA

Comandos útiles del día a día

az vm list -d -o table                                   # listar VM y su estado
az vm deallocate -g rg-demo -n vm-demo                   # apagar y dejar de pagar cómputo
az vm start -g rg-demo -n vm-demo                        # encender
az vm resize -g rg-demo -n vm-demo --size Standard_D2s_v5  # cambiar tamaño
az group delete -n rg-demo --yes --no-wait               # borrar TODO el proyecto

Cuidado: az group delete elimina de forma permanente todos los recursos del grupo. Verifica el nombre antes de ejecutarlo.

Problemas comunes y sus soluciones

Pulsa sobre cada problema para ver las causas probables y cómo resolverlo.

No puedo conectarme por SSH o RDP Red

Causas probables

  • La VM está apagada o aún iniciando.
  • El NSG no permite el puerto 22 (SSH) o 3389 (RDP) desde tu IP.
  • Tu IP pública cambió y ya no coincide con la regla.
  • El firewall del sistema operativo bloquea la conexión.
  • El servicio SSH/RDP no está en ejecución.

Solución

  1. Verifica en el portal que el estado sea En ejecución.
  2. Revisa Redes → Reglas de puerto de entrada y agrega tu IP actual.
  3. Usa Network Watcher → Solución de problemas de conexión para ver dónde se corta.
  4. Si nada funciona, entra por la Consola serie o usa Restablecer contraseña desde el portal.
az vm open-port -g rg-demo -n vm-demo --port 22
az vm show -d -g rg-demo -n vm-demo --query powerState
Mi sitio web en la VM no carga desde internet Red

Causas probables

  • El puerto 80 o 443 no está abierto en el NSG.
  • El servidor web (Apache, Nginx, IIS) no está iniciado.
  • La aplicación escucha solo en 127.0.0.1 y no en todas las interfaces.
  • Firewall del sistema operativo (ufw, firewalld, Windows Firewall).

Solución

  1. Abre los puertos 80/443 en el NSG.
  2. Comprueba el servicio: sudo systemctl status nginx.
  3. Verifica que escuche en 0.0.0.0: ss -tlnp.
  4. Permite el tráfico en el firewall local: sudo ufw allow 80,443/tcp.
La IP pública de mi servidor cambia al reiniciar Red

Causa

La IP pública se creó con asignación dinámica: puede cambiar cuando la VM se desasigna.

Solución

Cambia la dirección IP a estática desde Dirección IP pública → Configuración → Asignación → Estática, o configura un nombre DNS para la IP. Ten en cuenta que las IP estáticas pueden tener un costo asociado.

La VM está lenta o con CPU al 100 % Rendimiento

Causas probables

  • El tamaño de la VM es pequeño para la carga.
  • Serie B sin créditos de CPU suficientes (se limita el rendimiento).
  • Disco lento (HDD estándar) con muchas operaciones de lectura/escritura.
  • Un proceso consume demasiados recursos o hay poca RAM libre.

Solución

  1. Revisa Métricas en Azure Monitor: CPU, memoria, IOPS de disco y red.
  2. Identifica el proceso culpable con top/htop o el Administrador de tareas.
  3. Aumenta el tamaño de la VM (Tamaño → Cambiar) o pasa a una serie D.
  4. Cambia a un disco SSD premium si el cuello de botella es el almacenamiento.
El disco está lleno Rendimiento

Solución

  1. Busca qué ocupa espacio: du -sh /* 2>/dev/null | sort -h. Limpia logs y archivos temporales.
  2. Si necesitas más capacidad, desasigna la VM y amplía el disco desde Discos → Tamaño y rendimiento.
  3. Inicia la VM y extiende la partición y el sistema de archivos dentro del sistema operativo.
az vm deallocate -g rg-demo -n vm-demo
az disk update -g rg-demo -n NOMBRE_DISCO --size-gb 128
az vm start -g rg-demo -n vm-demo

Nota: los discos solo se pueden ampliar, no reducir. Haz un respaldo antes.

La VM no arranca o queda en “Error de inicio” Rendimiento

Causas probables

  • Sistema de archivos dañado, actualización fallida o archivo fstab incorrecto.
  • Cambio de configuración que impide el arranque.

Solución

  1. Activa y revisa Diagnósticos de arranque (captura de pantalla y registro serie).
  2. Entra por la Consola serie para corregir la configuración.
  3. Usa az vm repair para crear una VM de rescate y reparar el disco del sistema.
  4. Como último recurso, restaura desde un respaldo o una instantánea del disco.
Me cobran aunque tengo la VM “apagada” Costos

Causa

Si apagas la VM desde dentro del sistema operativo, queda en estado Detenida pero Azure sigue reservando el hardware y continúa cobrando el cómputo.

Solución

  1. Apaga desde el portal o CLI hasta que el estado sea Desasignada (Deallocated).
  2. Recuerda que discos, IP públicas estáticas y respaldos siguen generando cargos aunque la VM esté desasignada.
  3. Configura el apagado automático de la VM para entornos de prueba.
az vm deallocate -g rg-demo -n vm-demo
La factura de Azure es más alta de lo esperado Costos

Solución

  1. Abre Cost Management + Billing → Análisis de costos y agrupa por servicio o grupo de recursos.
  2. Busca recursos olvidados: discos sin adjuntar, IP públicas sin uso, VM encendidas sin necesidad.
  3. Crea presupuestos y alertas para que te avisen al acercarte al límite.
  4. Revisa las recomendaciones de Azure Advisor (redimensionar, apagar, reservar).
  5. Para cargas estables evalúa Reservas o Savings Plan.
Error de cuota o “SKU no disponible” al crear la VM Cuotas

Causas probables

  • Superaste el límite de núcleos (vCPU) de tu suscripción en esa región.
  • El tamaño elegido no está disponible en la región o zona seleccionada.

Solución

  1. Ve a Suscripciones → Uso y cuotas y solicita un aumento de cuota.
  2. Prueba otro tamaño de VM u otra región.
  3. Consulta disponibilidad: az vm list-skus --location eastus --size Standard_D -o table.
Olvidé la contraseña o perdí la clave SSH Acceso

Solución

  1. En el portal abre la VM y entra a Ayuda → Restablecer contraseña.
  2. Puedes cambiar la contraseña o cargar una nueva clave pública SSH.
  3. Desde la CLI:
az vm user update -g rg-demo -n vm-demo \
  --username azureuser --password 'NuevaClaveSegura#2026'
Borré datos o necesito recuperar el servidor Respaldo

Solución

  • Si tenías Azure Backup: ve al almacén de Recovery Services y restaura la VM o archivos concretos.
  • Si hiciste instantáneas del disco: crea un disco nuevo desde la instantánea y adjúntalo.
  • Si no hay respaldo, la recuperación no está garantizada: activa Azure Backup desde hoy.

Buenas prácticas

🔐

Seguridad

  • Usa claves SSH en lugar de contraseñas.
  • No abras RDP/SSH a todo internet; limita por IP o usa Azure Bastion / acceso Just-In-Time.
  • Activa Microsoft Defender for Cloud.
  • Mantén el sistema y el software actualizados.
💾

Respaldo y continuidad

  • Configura Azure Backup con retención adecuada.
  • Prueba restaurar de vez en cuando.
  • Para producción, usa zonas de disponibilidad o conjuntos de disponibilidad.
📈

Monitoreo

  • Habilita Azure Monitor y diagnósticos de arranque.
  • Crea alertas de CPU, disco y disponibilidad.
  • Centraliza registros en Log Analytics.
💰

Control de costos

  • Define presupuestos con alertas.
  • Apaga (desasigna) lo que no uses.
  • Ajusta el tamaño según el uso real.
  • Etiqueta los recursos por proyecto o equipo.
🗂️

Organización

  • Un grupo de recursos por proyecto o entorno.
  • Nombres consistentes, por ejemplo vm-web-prod-01.
  • Automatiza con Azure CLI, Bicep o Terraform.

Consejo final: empieza con un entorno de pruebas pequeño, practica los problemas de la sección anterior y, cuando tengas confianza, replica la configuración en producción.
